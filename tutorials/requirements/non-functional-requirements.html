Non-Functional Requirements

NFR-001 through NFR-006, with the concrete implementation evidence for each.

IDCategoryRequirementEvidence
NFR-001SecurityObject-level authorization on every endpoint; no tenant can access another's data by manipulating an id (IDOR).Queryset scoping by membership everywhere; tests/test_security_idor.py
NFR-002PerformanceList endpoints must not exhibit N+1 query growth as row count increases; expensive aggregates must be cached.select_related/prefetch_related on TaskViewSet; tests/test_performance.py; project-statistics Redis cache
NFR-003ReliabilityMulti-step writes that must succeed or fail together are wrapped in a transaction.@transaction.atomic throughout services; tests/test_transactions.py
NFR-004AvailabilityA slow/unavailable email provider must not block the request that triggered the email.send_password_reset_email as a Celery task
NFR-005MaintainabilityBusiness logic lives in a per-app service layer, not views/serializers.Every services.py; see Services
NFR-006TestabilityAutomated tests cover models, API behavior, business logic, security/IDOR, transactions, and query performance.17 files under tests/; see Test Cases

Throttling (1000/day authenticated, 100/day anonymous, 20/hour on auth endpoints) and pagination (20/page) round out the operational NFRs — see API Overview.
