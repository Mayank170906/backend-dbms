BackendDBMS Docs

Features, App by App

What's actually implemented, grouped by the Django app that owns it.

Every feature below is backed by a real model and service method — see Services for the exact call each one makes.

Accounts

  • Registration, login, logout with JWT access/refresh tokens (rotation + blacklist on logout).
  • Password reset request/confirm flow (always returns 200 to avoid revealing whether an account exists).
  • Authenticated "me" endpoint and a searchable user directory (UserViewSet).

Organizations & Teams

  • Organization creation (creator becomes OWNER automatically via OrganizationService.create_organization).
  • Membership management with roles OWNER/ADMIN/MEMBER/VIEWER.
  • Teams and team membership within an organization.

Workflows

  • Per-organization, admin-defined workflows: a Workflow has ordered WorkflowStates and explicit WorkflowTransitions.
  • Each transition can restrict which project roles are allowed to perform it (allowed_roles).

Projects

  • Projects scoped to an organization, each optionally bound to a workflow.
  • Per-project membership with roles MANAGER/DEVELOPER/VIEWER.
  • Project activity feed, computed statistics, and CSV task export (run asynchronously via Celery).

Tasks

  • Task CRUD with priority, due date, estimated hours, labels, and multiple assignees.
  • Workflow-governed state transitions (WorkflowService.transition_task) — a task can only move along transitions its workflow actually defines, and only by a role that transition allows.
  • Assignment, with an activity log entry and a notification to the assignee.

Comments

  • Threaded comments on tasks.
  • @username mention parsing that notifies only mentioned users who are actual project members (no notification for a mention of a non-member or a made-up username, and no self-notification).

Activity, Notifications, Analytics

  • An append-only ActivityLog (immutable — its save()/delete() are overridden to reject updates/deletes) recording task/comment/membership/workflow events.
  • A per-user Notification inbox (mark-read / mark-all-read) fed by the same service calls that write activity.
  • Cross-model full-text search across projects, tasks, and comments via Postgres SearchVectorField/GinIndex, exposed at /api/v1/search/.

Real-time

  • A per-project WebSocket feed (ws/projects/<id>/) broadcasting activity events to connected members.
  • A per-user WebSocket feed (ws/notifications/) broadcasting new notifications.
  • Both are JWT-authenticated at connect time and both are populated by transaction.on_commit() hooks, so a rolled-back change never produces a live event.
