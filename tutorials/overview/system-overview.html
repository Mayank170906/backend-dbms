System Overview

The system in one picture, before the deep dives.

At the highest level: a browser talks HTTP and WebSocket to a single Django/DRF/Channels application, which is the only thing that talks to PostgreSQL, and which hands background/scheduled work off to Celery through Redis.

Full component and deployment detail is in Architecture; the Redis/Celery/Channels boxes are configured in code but require real infrastructure wherever this is deployed — see Current Status.

For the request-by-request mechanics of how a single API call moves through this diagram, see Request Lifecycle. For how a change gets from one browser tab to another in real time, see Authentication Flow and Sequence Diagrams.
