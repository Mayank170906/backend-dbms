BackendDBMS Docs

Current Implementation Status

What's actually running in production versus configured-but-not-provisioned. Nothing here is aspirational.

This page exists specifically to prevent the rest of the documentation from being read as marketing copy. A setting existing in config/settings/base.py does not mean the corresponding infrastructure is deployed — see the Redis/Celery/Channels row below.

SubsystemStatusEvidence
Core Django app (accounts/orgs/projects/tasks/workflows/comments)ImplementedFull models, serializers, views, services, tests for all 9 apps.
JWT authenticationImplementeddjangorestframework-simplejwt, rotation + blacklist, covered by tests/test_auth_api.py.
Postgres full-text searchImplementedSearchVectorField/GinIndex on Project/Task/Comment, real SearchView.
Service-layer business logicImplementedEvery write path goes through services.py, wrapped in @transaction.atomic.
Test suiteImplemented17 test files under tests/; README reports 78 tests, ~90% coverage (a project-reported figure — see Coverage).
Docker image / Render deploymentImplementedLive at backend-dbms-p4su.onrender.com, built from the repo's Dockerfile.
Supabase PostgreSQL in productionImplementedDATABASE_URL-driven, see Supabase.
Redis (cache / Celery broker / Channels layer)Configured, requires infrastructureSettings default to redis://localhost:6379/*; a real Redis service must be provisioned wherever this is deployed for caching, Celery, and WebSockets to function — it is not automatically part of a Render web-service deployment. See Deployment → Render.
Celery worker & beat (async email/export/report/cleanup jobs)Configured, requires infrastructureReal tasks and a CELERY_BEAT_SCHEDULE exist and run under docker-compose.yml/docker-compose.prod.yml's worker/beat services, but depend on the same Redis provisioning above.
Django Channels / WebSocketsConfigured, requires infrastructureConsumers and JWT WS auth are fully implemented and tested (tests/test_websocket_consumers.py), but the Channels layer needs the same Redis dependency.
CI (automated test runs on push)Not implementedThe only workflow in .github/workflows/ deploys the tutorials/ site to GitHub Pages — nothing runs pytest automatically. Documented as a known gap in the README's "Future Improvements" section.
Object storage for media/exportsNot implementedUploads (User.avatar, ProjectExport.file) are written to the container's local filesystem (MEDIA_ROOT), not a persistent object store.
Sprints / iteration planningNot implementedNo Sprint model or app exists; listed in the README as a deferred feature.
