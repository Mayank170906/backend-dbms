Project Overview

What Backend DBMS is, who it's for, and why it exists.

What it is

Backend DBMS is a self-contained, multi-tenant workflow and project management platform — the same shape of product as Jira, Linear, or Trello — built end-to-end as a demonstration of production-grade Django backend engineering. Organizations own projects; projects run on administrator-configurable workflows; tasks move through those workflows, get assigned, commented on, and exported; and every meaningful change is logged and pushed to connected clients in real time.

"Multi-tenant" is not a marketing word here — it is the organizing constraint on the whole data model and permission system. Every organization's data (projects, tasks, comments, workflows) is completely isolated from every other organization's, enforced at the queryset level rather than only in the UI. See Actors and Permissions for how that isolation is actually implemented.

Why it exists

The project's purpose is to be a realistic, non-trivial backend that exercises the parts of Django/DRF engineering that a CRUD tutorial usually skips: a real relational schema with deliberate on_delete choices, a service layer that keeps business rules in one place, JWT authentication with rotation and blacklisting, Postgres full-text search, Redis-backed caching and rate limiting, Celery for background/scheduled work, and Django Channels for WebSocket-based real-time updates — all wired together and covered by an actual test suite. The Current Status page is explicit about which of those pieces are fully operational in the live deployment versus configured-but-not-yet provisioned.

Where it runs

The application is deployed as a Docker image on Render, backed by a Supabase-hosted PostgreSQL database, at backend-dbms-p4su.onrender.com. The source is at github.com/Mayank170906/backend-dbms. Full deployment details live under Deployment.
