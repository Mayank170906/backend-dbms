Why no custom middleware

There is no project-authored Django HTTP middleware — the stack is entirely stock Django + third-party packages (SecurityMiddleware, WhiteNoiseMiddleware, CorsMiddleware, SessionMiddleware, CommonMiddleware, CsrfViewMiddleware, AuthenticationMiddleware, MessageMiddleware, XFrameOptionsMiddleware). Everything project-specific happens further down the stack, in DRF authentication/permission classes and the service layer — see Codebase → Middleware.
