Architecture: Data Flow

How a single write moves from an HTTP body to a database row, using task creation as the running example.

Every write endpoint follows the same shape. Concretely, for POST /api/v1/tasks/:

Request bodyJSON
↓
TaskSerializerfield validation, validate_labels()
↓
TaskViewSet.perform_createapps/tasks/api/views.py
↓
TaskService.create_task@transaction.atomic
↓
Task.objects.create()Django ORM
ActivityService.log()same transaction
↓
PostgreSQLtasks_task, activity_activitylog rows committed together
↓
TaskSerializer (response)201 Created

Two details matter here and recur throughout the codebase:

  • Validation happens before any write. TaskSerializer.validate_labels rejects labels belonging to a different project than the task before TaskService.create_task is ever called.
  • The write and its audit trail are one transaction. If ActivityService.log() raised, the Task row would roll back too — verified directly by tests/test_transactions.py, which monkeypatches a failure partway through to prove the rollback actually happens rather than just assuming @transaction.atomic is doing its job.
