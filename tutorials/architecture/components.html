Architecture: Components

The support modules in config/ that glue the apps together.

Beyond the 9 Django apps, a handful of modules in config/ do the cross-cutting wiring. None of them own models — they route, configure, or translate.

ModuleRole
config/urls.pyRoot URLconf: mounts admin/, api/v1/ (via api_router.py), the OpenAPI schema/docs routes, and a handful of TemplateView-only server-rendered pages (dashboard/login/register/etc.) that make zero ORM calls.
config/api_router.pyThe single DRF DefaultRouter registration point for every ViewSet in the project, mounted at /api/v1/. See Codebase → URLs for the full table.
config/routing.pyCombines each app's WebSocket URL patterns (apps/projects/routing.py, apps/notifications/routing.py) into one list, imported by asgi.py.
config/channels_auth.pyCustom ASGI middleware (JWTAuthMiddleware/JWTAuthMiddlewareStack) that authenticates a WebSocket connection from a ?token= query parameter, since a browser can't set a custom header during the WS handshake.
config/exceptions.pycustom_exception_handler — wraps every DRF error response in a consistent {"error": {...}} envelope. See API → Error Handling.
config/celery.pyConstructs the Celery("backend_dbms") app, points it at Django settings under the CELERY namespace, and autodiscovers each app's tasks.py.
config/asgi.pyBuilds the single ProtocolTypeRouter that routes HTTP to Django and WebSocket to JWTAuthMiddlewareStack(URLRouter(...)) — the one process that serves both protocols in production.
config/settings/{base,development,production}.pySee Codebase → Configuration for the full walkthrough.
