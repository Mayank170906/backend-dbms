API: Architecture

How authentication, permissions, filtering, pagination, throttling, and schema fit together as one DRF configuration.

All of this is configured once, globally, in REST_FRAMEWORK (config/settings/base.py) — individual viewsets only add additional permission classes or filter fields on top, they don't redefine the defaults: 

REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": ["rest_framework_simplejwt.authentication.JWTAuthentication"],
    "DEFAULT_PERMISSION_CLASSES": ["rest_framework.permissions.IsAuthenticated"],
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 20,
    "DEFAULT_FILTER_BACKENDS": [
        "django_filters.rest_framework.DjangoFilterBackend",
        "rest_framework.filters.SearchFilter",
        "rest_framework.filters.OrderingFilter",
    ],
    "DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema",
    "EXCEPTION_HANDLER": "config.exceptions.custom_exception_handler",
    ...
}

This is why every endpoint in Endpoints is IsAuthenticated by default (register/login/password-reset explicitly opt out with AllowAny), why every list response is paginated the same way, and why the error envelope in Error Handling is identical across every app — it's one configuration point, not per-view boilerplate. See Codebase → Configuration for the rest of this settings file.
