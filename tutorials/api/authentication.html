API: Authentication

JWT bearer tokens for HTTP, a query-string token for WebSocket.

Authorization: Bearer <access_token>
SettingValue
ACCESS_TOKEN_LIFETIME30 minutes
REFRESH_TOKEN_LIFETIME7 days
ROTATE_REFRESH_TOKENSTrue
BLACKLIST_AFTER_ROTATIONTrue
EndpointMethodPurpose
/api/v1/auth/register/POSTCreate a user
/api/v1/auth/login/POSTIssue access + refresh tokens
/api/v1/auth/login/refresh/POSTRotate the refresh token, issue a new access token
/api/v1/auth/logout/POSTBlacklist the submitted refresh token

WebSocket connections (ws/projects/<id>/, ws/notifications/) authenticate differently — via ?token=<access_token>, validated by the custom JWTAuthMiddleware in config/channels_auth.py, because a browser can't set a custom header during the WebSocket handshake. See Authentication Flow for the full step-through diagram.
