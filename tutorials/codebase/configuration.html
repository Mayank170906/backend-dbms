Codebase: Configuration

How config/settings/{base,development,production}.py fit together.

Settings are a package, not a single file, imported as from .base import * in both development.py and production.py — never edited independently for each environment.

base.py

  • SECRET_KEY = os.environ.get("SECRET_KEY", "") — no hardcoded fallback here (only in development).
  • Two small helpers, env_bool() and env_list(), parse boolean/comma-separated env vars consistently — see Utilities.
  • .env is loaded via python-dotenv's load_dotenv() at import time, without overriding real environment variables that are already set.
  • DATABASES comes entirely from dj_database_url.config(env="DATABASE_URL", conn_max_age=600, conn_health_checks=True) — one variable, one source of truth.
  • ASGI_APPS = ["daphne"] is listed first in INSTALLED_APPS, ahead of django.contrib.staticfiles, specifically so Channels can override runserver to also handle WebSocket connections in development.
  • STORAGES["staticfiles"] is whitenoise.storage.CompressedManifestStaticFilesStorage — content-hashed, pre-compressed static files.
  • JWT (SIMPLE_JWT), DRF (REST_FRAMEWORK), Celery (CELERY_* + CELERY_BEAT_SCHEDULE), cache (CACHES), and Channels (CHANNEL_LAYERS) are all fully configured here — see API Overview, Environment Variables, and Services respectively.
  • LOGGING is a single console StreamHandler at a level from DJANGO_LOG_LEVEL (default INFO) — there are no file handlers or per-app loggers.

development.py

  • DEBUG = True.
  • SECRET_KEY falls back to a hardcoded, clearly-named insecure value if the env var is unset — a convenience meant only for a laptop, never anywhere reachable over a network.
  • CORS_ALLOW_ALL_ORIGINS = True — acceptable because dev never serves real user data.

production.py

  • Raises RuntimeError at import time if SECRET_KEY, ALLOWED_HOSTS, or DATABASE_URL is unset or empty — the app refuses to even start misconfigured in production, rather than starting insecurely.
  • DEBUG = False, JSON-only DRF renderer (browsable API disabled), CORS_ALLOW_ALL_ORIGINS = False.
  • Forces SECURE_SSL_REDIRECT (default True), SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE, CSRF_COOKIE_HTTPONLY, SECURE_HSTS_SECONDS (default one year) with subdomains + preload, SECURE_CONTENT_TYPE_NOSNIFF, X_FRAME_OPTIONS = "DENY", and reads SECURE_PROXY_SSL_HEADER so Django trusts Render's X-Forwarded-Proto.
  • CSRF_TRUSTED_ORIGINS comes from its own env var — nothing is trusted by default.

Full production security posture is on Deployment → Production Configuration.
