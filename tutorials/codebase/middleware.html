Codebase: Middleware

No custom Django middleware exists — here's the real stack and why JWTAuthMiddleware doesn't count.

There is no project-authored Django HTTP middleware in this codebase. This page states that plainly rather than implying otherwise.

The real middleware stack

config/settings/base.py's MIDDLEWARE list, in order — entirely stock Django and third-party packages:

SecurityMiddleware
WhiteNoiseMiddleware
CorsMiddleware
SessionMiddleware
CommonMiddleware
CsrfViewMiddleware
AuthenticationMiddleware
MessageMiddleware
XFrameOptionsMiddleware

JWTAuthMiddleware is not Django middleware

The one project-authored class that looks like middleware — JWTAuthMiddleware in config/channels_auth.py — is Channels ASGI middleware, wrapping the WebSocket protocol router (JWTAuthMiddlewareStack(URLRouter(...)) in config/asgi.py). It never runs on HTTP requests and is unrelated to Django's MIDDLEWARE setting. See Authentication Flow.
