Codebase: Services

Every service class and method — the layer that owns all business logic.

Every write path in the app goes through a services.py class method, never directly through a view or a raw .objects.create() in a viewset. This is the project's single most important architectural rule — see ADRs for why.

organizations
  • OrganizationService.create_organization(*, owner, name, description="") — atomic; creates the org and an OWNER membership.
  • OrganizationService.add_member(*, organization, user, role=MEMBER) — atomic upsert.
  • TeamService.create_team(*, organization, name, description="").
  • TeamService.add_member(*, team, user) — get_or_create.
projects
  • ProjectService.create_project(*, organization, owner, name, description="") — atomic; creates the project and a MANAGER membership for the owner.
  • ProjectService.add_member(*, project, user, actor, role=DEVELOPER) — atomic upsert; logs activity, notifies on creation.
  • caching.py: project_statistics_cache_key(*, project_id), invalidate_project_statistics(*, project_id).
  • statistics.py: get_project_statistics(*, project) — cache-aside wrapper around _compute_project_statistics and _completion_metrics.
tasks
  • TaskService.create_task(*, project, created_by, title, description="", priority=MEDIUM, due_date=None, estimated_hours=None) — atomic; also logs activity.
  • TaskService.assign(*, task, user, actor) — atomic; logs activity, notifies the assignee.
  • TaskService.add_label(*, task, label) — enforces the cross-project label guard.
comments
  • CommentService.add_comment(*, task, author, body) — atomic; membership check, logs activity, triggers mention notifications.
  • CommentService._notify_mentions(*, comment, task, author) — parses @username via regex, notifies only mentioned users who are actual project members.
workflows
  • WorkflowService.create_workflow(*, organization, name, description="", actor=None).
  • WorkflowService.add_state(*, workflow, name, order, is_initial=False, is_terminal=False, actor=None).
  • WorkflowService.add_transition(*, workflow, from_state, to_state, allowed_roles, actor=None) — validates roles against ProjectMembership.Role.
  • WorkflowService.transition_task(*, task, to_state, user) — the sole authority for task state transitions: checks membership, transition existence, and role gating, then logs activity and notifies other assignees.
activity

ActivityService.log(*, actor, action, target, organization, project=None, metadata=None) — creates the audit row; if project is given, broadcasts via transaction.on_commit() to broadcast_activity_event.

notifications
  • NotificationService.notify(*, recipient, notification_type, message, target=None) — creates the row, broadcasts via on_commit().
  • NotificationService.mark_read(*, notification) / mark_all_read(*, user).
