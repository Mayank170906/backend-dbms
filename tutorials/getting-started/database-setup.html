Getting Started: Database Setup

Getting a local Postgres database migrated and (optionally) seeded.

Two ways to get a local Postgres instance, matching the two run modes:

Option A — via Docker Compose

The db service in docker-compose.yml (postgres:16-alpine, with a pg_isready healthcheck) is started automatically by docker compose up — see Running with Docker. Its connection details are wired into DATABASE_URL by the compose file's shared env block.

Option B — native Postgres

Point DATABASE_URL in your .env at a Postgres instance you run yourself, e.g.:

DATABASE_URL=postgresql://postgres:postgres@localhost:5432/backend_dbms

Apply migrations

uv run python manage.py migrate

Optional: seed realistic demo data

uv run python manage.py seed_data
# or, to wipe and recreate the demo data:
uv run python manage.py seed_data --clear

seed_data (apps/organizations/management/commands/seed_data.py) creates 3 demo organizations ("Demo: Acme Corp", "Demo: Globex Industries", "Demo: Initech"), users, teams, workflows, projects, tasks, labels, and comments — entirely through the real service layer (OrganizationService, ProjectService, TaskService, etc.), not raw .objects.create() calls, so the seeded data exercises the same code paths as real usage.
