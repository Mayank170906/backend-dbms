Getting Started: Running with Docker

The full stack — app, database, Redis, worker, beat — in one command.

docker compose up

This starts every service defined in docker-compose.yml:

ServiceImage / buildCommandNotes
dbpostgres:16-alpine—Port 5432 published; pg_isready healthcheck; data in the postgres_data volume.
redisredis:7-alpine—Port 6379 published; redis-cli ping healthcheck; data in the redis_data volume.
webbuilt from the repo's Dockerfilepython manage.py runserver 0.0.0.0:8000Source bind-mounted (.:/app) for live reload; port 8000 published; media_data volume for uploads.
workersame image as webcelery -A config worker --loglevel=infoSame source mount.
beatsame image as webcelery -A config beat --loglevel=infoSame source mount; writes the schedule DB.

A shared x-app-env anchor points DATABASE_URL at the db service by name and REDIS_URL/ CELERY_BROKER_URL/CELERY_RESULT_BACKEND/ CACHE_URL/CHANNELS_REDIS_URL at the redis service on DB indexes 0/0/1/2/3 respectively — so every service in this stack sees a fully working Redis and Postgres without you configuring anything by hand.

Full walkthrough of the underlying Dockerfile and how it differs from the production compose file is on Deployment → Docker.
