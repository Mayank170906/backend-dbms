Developer Notes: ORM Notes

on_delete choices, N+1 avoidance, transactions, and Postgres-specific fields.

on_delete is a modeling decision, not a default

See Database → Relationships for the full PROTECT/CASCADE/SET_NULL breakdown — the short version: PROTECT for single-owner relationships, CASCADE for dependent rows that have no meaning alone, SET_NULL for high-cardinality attribution fields.

Avoiding N+1 queries

TaskViewSet.get_queryset() uses select_related (for single-valued FKs like created_by, workflow_state) and prefetch_related (for the labels/assignees many-to-manys) so that listing N tasks doesn't issue N additional queries for their related objects. tests/test_performance.py asserts the query count with a fixed budget rather than trusting this by inspection alone.

Transactions wrap "the write plus its consequences"

Every service method that both writes a row and logs/notifies wraps both in @transaction.atomic — e.g. TaskService.assign creates the TaskAssignment and calls ActivityService.log/NotificationService.notify in one transaction. tests/test_transactions.py deliberately breaks the second half (via monkeypatching) to prove the first half also rolls back.

Postgres-specific fields, used for real

ArrayField (WorkflowTransition.allowed_roles) avoids a join table for a small, unordered set of role strings. SearchVectorField + GinIndex (Project/Task/Comment) gives indexed full-text search without a separate search service.
