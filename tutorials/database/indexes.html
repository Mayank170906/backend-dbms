Database: Indexes

Every real Index and GinIndex, tied to the query it serves.

ModelIndexServes
OrganizationIndex(["name"])directory-style lookups
MembershipIndex(["organization","role"])"who are the admins of org X" queries
ProjectIndex(["organization","status"])the filterset_fields=["organization","status"] filter on ProjectViewSet
ProjectGinIndex(["search_vector"], name="project_search_vector_gin")full-text search
ProjectMembershipIndex(["project","role"])"who are the managers of project X"
TaskIndex(["project","priority"]), Index(["project","due_date"]), Index(["project","workflow_state"])the task list's common filter/sort combinations
TaskGinIndex(["search_vector"], name="task_search_vector_gin")full-text search
CommentIndex(["task","created_at"])fetching a task's comment thread in order
CommentGinIndex(["search_vector"], name="comment_search_vector_gin")full-text search
ActivityLogIndex(["organization","created_at"]), Index(["project","created_at"]), Index(["content_type","object_id"])org/project activity feeds, plus GFK reverse lookups
NotificationIndex(["recipient","is_read"])a user's unread-notification count/list

tests/test_performance.py asserts the task list's query count stays fixed regardless of row count — see Developer Notes → ORM Notes for the select_related/prefetch_related side of that.
