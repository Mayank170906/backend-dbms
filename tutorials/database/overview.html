Database Overview

PostgreSQL, reached through a single DATABASE_URL, chosen for two features this project actually uses.

PostgreSQL is the only system of record — Supabase-hosted in production, a compose-managed postgres:16-alpine container in dev. Both are reached through exactly one setting, DATABASE_URL, parsed by dj_database_url.config(). There is no separate read replica, cache database, or secondary store for any model data.

Why Postgres specifically

Two Postgres-native features are used directly by real models, not just theoretically available: full-text search (SearchVectorField + GinIndex on Project, Task, Comment) and ArrayField (WorkflowTransition.allowed_roles). Both would need either a separate search service or an extra join table on MySQL/SQLite. SQLite specifically also can't hold up under the concurrent writes this system needs once Celery workers and the web process write at the same time.

See ER Diagram for the full schema, and Deployment → Supabase for the production connection details.
