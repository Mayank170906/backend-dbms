Database: Migrations

How schema changes are generated and applied, and the real production gotcha.

uv run python manage.py makemigrations   # generate, after changing models.py
uv run python manage.py migrate           # apply

Three migrations are worth naming specifically, since they're what adds full-text search to the schema:

  • apps/projects/migrations/0004_project_search_vector_and_more.py
  • apps/tasks/migrations/0003_task_search_vector_task_task_search_vector_gin.py
  • apps/comments/migrations/0003_comment_search_vector_and_more.py

The real production gotcha

A freshly provisioned database (a new Supabase project, for instance) has no schema until migrate runs against it — Django will report something like "you have N unapplied migrations" until it does. That number is a point-in-time fact about a specific database's state, not a stable property of the codebase, so this documentation doesn't claim any particular count is currently outstanding anywhere — only that a fresh database needs migrate run once before the schema matches the models. See Deployment → Troubleshooting.
