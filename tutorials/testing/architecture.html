Test Architecture

pytest + pytest-django + pytest-asyncio, all tests centralized under one top-level directory.

Every test lives under the top-level tests/ directory (17 files) — not inside each app, which is a deliberate departure from Django's per-app tests.py convention, chosen so a test can freely exercise multiple apps together (a task transition test touches tasks, workflows, activity, and notifications in one flow). 

[tool.pytest.ini_options]
DJANGO_SETTINGS_MODULE = "config.settings.development"
python_files = ["test_*.py"]
testpaths = ["tests"]
addopts = "--reuse-db"
asyncio_mode = "auto"
  • pytest-django provides the db fixture and Django test client integration; --reuse-db skips recreating the test database on every run (drop it manually after a schema change with --create-db once).
  • pytest-asyncio (asyncio_mode = "auto") is required specifically for tests/test_websocket_consumers.py, which drives Channels' async test client.
  • pytest-cov scopes coverage to source = ["apps"], omitting */migrations/* and */tests/*.
