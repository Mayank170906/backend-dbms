Deployment: Docker

The Dockerfile, and how the dev and prod compose files differ.

Dockerfile

# syntax=docker/dockerfile:1
FROM python:3.12-slim AS base

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    UV_LINK_MODE=copy \
    UV_PROJECT_ENVIRONMENT=/usr/local

RUN apt-get update \
    && apt-get install -y --no-install-recommends libpq5 \
    && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:0.8.14 /uv /usr/local/bin/uv
WORKDIR /app

COPY pyproject.toml uv.lock ./
RUN --mount=type=cache,target=/root/.cache/uv \
    apt-get update \
    && apt-get install -y --no-install-recommends build-essential libpq-dev \
    && uv sync --frozen --no-install-project --no-dev \
    && apt-get purge -y build-essential libpq-dev \
    && apt-get autoremove -y \
    && rm -rf /var/lib/apt/lists/*

COPY . .
RUN chmod +x docker/entrypoint.sh

RUN SECRET_KEY=build-time-placeholder-unused-at-runtime \
    ALLOWED_HOSTS=localhost \
    DATABASE_URL=postgres://build:build@localhost/build \
    python manage.py collectstatic --noinput --settings=config.settings.production

RUN groupadd --system app && useradd --system --gid app --home /app app \
    && mkdir -p /app/media \
    && chown -R app:app /app
USER app

EXPOSE 8000
ENTRYPOINT ["docker/entrypoint.sh"]
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]

Notes on specific choices:

  • Dependencies installed before source is copied — so the dependency-install layer stays cached across builds unless pyproject.toml/uv.lock actually change.
  • Build tools installed, used, then purged in the same layer (build-essential libpq-dev) — they're only needed to build any dependency without a prebuilt wheel; libpq5 alone is what's needed at runtime.
  • collectstatic runs at build time against placeholder values — static assets are content-hashed by ManifestStaticFilesStorage, not by SECRET_KEY or the database, so this is safe. See Troubleshooting for why this specific trick exists.
  • Runs as a non-root user in every environment, dev included — one Dockerfile, one behavior to reason about.
  • ENTRYPOINT docker/entrypoint.sh waits for Postgres to accept connections (a retry loop using dj_database_url + psycopg) before exec-ing whatever CMD was given — this is what lets web/worker/beat all start reliably even if the db container is still initializing.
