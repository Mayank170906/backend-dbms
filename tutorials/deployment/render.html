Deployment: Render

How this project is actually deployed in production — a Docker image built from this repo, run as a Render Web Service, talking to Supabase Postgres.

Locally, Django talks to Postgres on 127.0.0.1 — the same machine. In production there is no such thing: Render runs the container, Supabase runs the database, and they only meet through a connection string. Everything below follows from that one fact. Live at backend-dbms-p4su.onrender.com.

1. Point Django at DATABASE_URL, not localhost

import os
import dj_database_url

DATABASE_URL = os.environ.get("DATABASE_URL")

if DATABASE_URL:
    DATABASES = {
        "default": dj_database_url.parse(
            DATABASE_URL,
            conn_max_age=600,
            ssl_require=True,
        )
    }

Note .get(...) rather than os.environ[...] — see step 6.

2. Generate a production SECRET_KEY

python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"

3. Set the production settings module and ALLOWED_HOSTS

# Correct
ALLOWED_HOSTS=backend-dbms-p4su.onrender.com,localhost,127.0.0.1

# Wrong — no https:// here
ALLOWED_HOSTS=https://backend-dbms-p4su.onrender.com

4. Render environment variables

DJANGO_SETTINGS_MODULE=config.settings.production
DEBUG=False
ALLOWED_HOSTS=backend-dbms-p4su.onrender.com
SECRET_KEY=YOUR_GENERATED_DJANGO_SECRET_KEY
DATABASE_URL=YOUR_SUPABASE_DATABASE_URL

5. Don't require DATABASE_URL at Docker build time

Render builds the image before the runtime environment exists. If a management command hard-requires DATABASE_URL via os.environ["DATABASE_URL"], the build fails before the app ever reaches Render's runtime — which is exactly why step 1 uses .get(...). 

RUN SECRET_KEY=build-time-placeholder-unused-at-runtime \
    ALLOWED_HOSTS=localhost \
    DATABASE_URL=postgres://build:build@localhost/build \
    python manage.py collectstatic --noinput \
    --settings=config.settings.production

6. Bind to 0.0.0.0:$PORT

daphne -b 0.0.0.0 -p $PORT config.asgi:application

7. Deploy and apply migrations

Django version 6.1.1, using settings 'config.settings.production'
Starting ASGI/Daphne ...
Listening on TCP address 0.0.0.0:8000
==> Your service is live
python manage.py migrate

Where the plan supports it, run migrate as a pre-deploy/release step rather than on every web-process restart.

Production checklist

  • DEBUG=False, settings module is config.settings.production
  • SECRET_KEY generated and stored only in Render
  • DATABASE_URL points at Supabase, not localhost
  • Supabase password never committed to GitHub
  • ALLOWED_HOSTS includes the Render hostname, no scheme prefix
  • Docker build doesn't hard-require DATABASE_URL
  • Migrations applied against Supabase after each schema change
  • Redis/Celery/Channels wired to a real service, or intentionally left unused — see Current Status
